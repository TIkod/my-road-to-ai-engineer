# My Road to AI Engineer

Мой путь из Fullstack-разработки в **AI Engineering**: пошаговое изучение тем, разборы, самопроверка и код.

Цель — стать прикладным AI-инженером, который строит продакшен-системы на основе LLM. Это значит уметь:

- подключать модели разных провайдеров и встраивать их в backend-сервисы;
- получать от модели предсказуемый результат: structured output, tool calling, промпты как код с версиями и тестами;
- строить RAG-системы, которые отвечают по реальным данным компании со ссылками на источники;
- разрабатывать агентов, которые выполняют многошаговые задачи через инструменты и MCP, с памятью и подтверждением человеком перед важными действиями;
- измерять качество LLM-систем с помощью evals, а не на глаз;
- выводить решения в продакшен: трейсинг, контроль стоимости и задержек, защита от prompt injection;
- делать системы надёжными: ретраи, fallback на другого провайдера, очереди для долгих задач;
- разворачивать AI-сервисы в облаке и работать с локальными open-source моделями;
- создавать интерфейсы со стримингом ответов: веб-чаты и Telegram-боты;
- понимать, когда LLM не нужна и задачу лучше решит классический ML или обычный код.

## Структура

Каждая часть (`partN/`) посвящена одной теме и проходит один и тот же цикл:

| Файл                                 | Этап                                                      |
| ------------------------------------ | --------------------------------------------------------- |
| `<topic>.md`                         | Обзор темы                                                |
| `my_questions_N.md` → `answers_N.md` | Мои вопросы и подробные разборы с примерами кода          |
| `summary.md`                         | Итоговый конспект для повторения                          |
| `test.md`                            | Тест по теме: ответы пишутся письменно, затем проверяются |
| `code/`                              | Практическая реализация                                   |

## Части

### [Part 1](part1/). LLM как инженерный компонент

🟡 Теория изучена, впереди тест

Как устроены LLM на уровне инженера, который их использует: токены, эмбеддинги, внимание, генерация, обучение, ограничения, стоимость запросов, основы RAG и чанкинга.

### [Part 2](part2/). Работа с LLM через API

🟡 В процессе: обзор темы и код

Вызов моделей из Python: запрос и ответ, роли и system prompt, история диалога, стриминг, обработка ошибок, переключение между провайдерами (fallback), логирование токенов и цены. Примеры работают на бесплатном API Groq через OpenAI-совместимый формат.
