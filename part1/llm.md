# LLM — Large Language Model (большая языковая модель)

## 1. Что это такое в одном абзаце

**LLM** — это нейросеть, обученная на огромном количестве текста, которая умеет **предсказывать следующий кусочек текста** по предыдущему. Звучит скромно, но если делать это очень хорошо на триллионах слов, модель вынужденно «выучивает» грамматику, факты о мире, логику, стили письма, языки программирования и даже умение рассуждать. В итоге получается универсальный инструмент: на вход текст, на выход текст.

Примеры LLM: Claude (Anthropic), GPT (OpenAI), Gemini (Google), Llama (Meta), Mistral, Qwen, DeepSeek.

Разберём название:

| Слово | Что значит |
|---|---|
| **Large** | Большая: миллиарды (и больше) параметров, обучение на триллионах токенов |
| **Language** | Работает с языком: текст, код, а у современных моделей ещё и картинки, аудио |
| **Model** | Математическая модель: по сути, огромная функция с подобранными числами-весами |

---

## 2. Зачем это нужно

Раньше под каждую задачу с текстом делали отдельную модель: одна классифицирует отзывы, другая переводит, третья вытаскивает имена из документов. LLM — это **одна модель на всё**, которой задачу объясняют обычным языком.

Что с помощью LLM делают на практике:

- **Генерация текста** — письма, статьи, описания товаров, документация.
- **Суммаризация** — сжать длинный документ, переписку, созвон до главного.
- **Извлечение данных** — достать из договора даты, суммы, стороны и вернуть JSON.
- **Классификация** — определить тональность, тему, приоритет тикета.
- **Перевод и переформулирование.**
- **Работа с кодом** — написать, объяснить, отрефакторить, найти баг.
- **Ответы на вопросы по своим данным** (RAG) — чат-бот по базе знаний компании.
- **Агенты** — модель сама вызывает инструменты (поиск, API, базы данных, терминал) и выполняет многошаговые задачи.

Главная ценность: то, что раньше требовало команды ML-инженеров и месяцев работы, теперь часто решается промптом и вызовом API за день.

## 3. Как это работает

### 3.1. Токены — как модель «видит» текст

Модель не читает буквы или слова напрямую. Текст сначала режется на **токены** — кусочки слов. Это делает **токенизатор**.

```
"Привет, как дела?"  →  ["При", "вет", ",", " как", " дела", "?"]
                    →  [ 4821,  1093,  11,   2310,   7742,   30]
```

Каждый токен получает номер в словаре (обычно словарь на 50–200 тысяч токенов). Модель работает только с этими числами.

Почему это важно знать:
- **Цена API считается в токенах** (входные и выходные отдельно).
- **Лимиты модели** (контекстное окно, длина ответа) тоже в токенах.
- Грубо: в английском 1 токен ≈ 0.75 слова, в русском токенов на то же количество слов обычно больше.
- Из-за токенов модели иногда плохо считают буквы в слове: они видят не буквы, а кусочки.

### 3.2. Эмбеддинги — превращаем токены в смысл

Номер токена сам по себе ничего не значит. Поэтому каждый токен превращается в **эмбеддинг** — вектор из тысяч чисел. Эти векторы подбираются в процессе обучения так, что похожие по смыслу токены оказываются «рядом» в этом многомерном пространстве.

Классический пример: `король − мужчина + женщина ≈ королева`.

> Эмбеддинги ты ещё встретишь отдельно: на них строится семантический поиск и RAG.

### 3.3. Трансформер и механизм внимания

Почти все современные LLM построены на архитектуре **Transformer** (статья Google «Attention Is All You Need», 2017).

Ключевая идея — **механизм внимания (attention)**: при обработке каждого токена модель смотрит на все предыдущие токены и решает, какие из них важны для понимания текущего.

```
"Кот сел на коврик, потому что он устал."
                                 ↑
                    "он" — это кто? Attention «смотрит» назад
                    и даёт большой вес слову "Кот", а не "коврик".
```

Трансформер — это много (десятки) одинаковых слоёв, стоящих друг за другом. Каждый слой:
1. **Attention** — токены «обмениваются информацией» друг с другом.
2. **Feed-forward сеть** — каждый токен отдельно «обдумывается».

Чем глубже слой, тем более абстрактные вещи он улавливает: сначала грамматика, потом смысл, потом логические связи.

**Параметры (веса)** — это все числа внутри этих слоёв. Именно их подбирают при обучении. «Модель на 70B» = 70 миллиардов таких чисел.

### 3.4. Предсказание следующего токена

На выходе модель выдаёт **распределение вероятностей** по всему словарю: насколько вероятен каждый токен следующим.

```
Вход: "Столица Франции —"

Выход:
  " Париж"   0.92
  " город"   0.03
  " это"     0.01
  ...
```

Дальше выбирается один токен, дописывается к тексту, и всё повторяется. Так ответ генерируется **по одному токену за раз** — поэтому в чатах текст «печатается» постепенно (это называется streaming).

```
"Столица Франции —" → " Париж"
"Столица Франции — Париж" → "."
"Столица Франции — Париж." → <конец>
```

Такой способ называется **авторегрессионной генерацией**.

### 3.5. Как выбирается токен: temperature и другие настройки

Можно всегда брать самый вероятный токен, а можно выбирать случайно с учётом вероятностей. Этим управляют параметры:

| Параметр | Что делает |
|---|---|
| **temperature** | «Креативность». Низкая (0–0.3) — предсказуемые, стабильные ответы. Высокая (0.8–1+) — разнообразнее, но больше риска чуши |
| **top_p** | Выбирать только из самых вероятных токенов, чья суммарная вероятность ≤ p |
| **top_k** | Выбирать только из k самых вероятных токенов |
| **max_tokens** | Максимальная длина ответа |
| **stop sequences** | Строки, на которых генерация остановится |

Правило на старте: для извлечения данных и классификации — низкая temperature, для креатива — повыше.

### 3.6. Контекстное окно

**Контекстное окно** — сколько токенов модель может «держать в голове» за один запрос: системный промпт + история диалога + документы + ответ. У современных моделей это от десятков тысяч до миллиона токенов.

Важно: **у модели нет памяти между запросами**. Каждый вызов API — с чистого листа. «Память» в чат-ботах — это когда приложение каждый раз заново отправляет всю историю переписки в контексте.

## 4. Как LLM обучают

Обучение идёт в несколько этапов.

### Этап 1. Pre-training (предобучение)

- Модели дают триллионы токенов текста: интернет, книги, код, статьи.
- Задача одна: угадать следующий токен. Ошиблась — веса чуть-чуть подкручиваются (градиентный спуск).
- Требует тысяч GPU на месяцы и стоит десятки–сотни миллионов долларов.
- Результат — **базовая модель (base model)**. Она много знает, но просто продолжает текст. Спросишь «Как испечь пирог?» — она может продолжить списком других вопросов, а не ответить.

### Этап 2. Fine-tuning на инструкциях (SFT, Supervised Fine-Tuning)

- Модель дообучают на примерах вида «вопрос → хороший ответ», написанных людьми.
- Модель учится быть **ассистентом**: отвечать на вопросы, следовать инструкциям, вести диалог.

### Этап 3. Обучение на предпочтениях (RLHF и аналоги)

- **RLHF** — Reinforcement Learning from Human Feedback. Люди сравнивают несколько ответов модели и выбирают лучший; модель учится выдавать то, что люди предпочитают.
- Есть варианты: RLAIF / Constitutional AI (оценивает другая модель по набору принципов), DPO и др.
- Также сюда относится обучение рассуждению: модель учат решать задачи с проверяемым ответом (математика, код) и награждают за правильный результат.
- Цель: сделать модель полезной, честной и безопасной.

```
 Тексты из интернета ──► [Pre-training] ──► Base model
                                                │
 Примеры диалогов ─────► [SFT] ─────────────────┤
                                                │
 Оценки/предпочтения ──► [RLHF / RL] ───────────┴──► Модель-ассистент (Claude, ChatGPT...)
```

## 5. Ограничения и подводные камни

Это нужно понимать каждому AI-инженеру — большая часть работы как раз в том, чтобы обходить эти ограничения.

| Проблема | Суть | Что с этим делают |
|---|---|---|
| **Галлюцинации** | Модель уверенно выдумывает факты, ссылки, API. Она генерирует *правдоподобный* текст, а не *проверенный* | RAG, ссылки на источники, проверка ответа, просьба говорить «не знаю» |
| **Knowledge cutoff** | Знания заморожены на дате окончания обучения | Поиск в интернете, RAG, передача актуальных данных в контексте |
| **Нет памяти** | Каждый запрос независим | Передавать историю, хранить память во внешней БД |
| **Ограниченный контекст** | Всё не влезет, а на очень длинном контексте качество может падать | Чанкинг, RAG, суммаризация истории |
| **Недетерминированность** | Один и тот же запрос может давать разные ответы | Низкая temperature, структурированный вывод, валидация, evals |
| **Чувствительность к промпту** | Мелкая переформулировка меняет результат | Промпт-инжиниринг, тесты на наборе примеров |
| **Prompt injection** | Вредные инструкции, спрятанные в данных (письме, веб-странице), могут перехватить управление | Разделение инструкций и данных, ограничение прав агентов, проверки |
| **Стоимость и задержка** | Большие модели дороже и медленнее | Выбор модели под задачу, кэширование промптов, батчи |

## 6. Как с LLM работает AI-инженер

AI-инженер обычно **не обучает LLM с нуля** — он строит продукты поверх готовых моделей. Основные инструменты по возрастанию сложности:

1. **Промпт-инжиниринг** — правильно сформулировать задачу: роль, контекст, примеры (few-shot), формат ответа.
2. **Структурированный вывод** — заставить модель возвращать валидный JSON по схеме, чтобы с ним мог работать код.
3. **RAG (Retrieval-Augmented Generation)** — найти релевантные куски из своих документов (через эмбеддинги и векторную БД) и подложить их в промпт. Модель отвечает по твоим данным, а не по памяти.
4. **Tool use / function calling** — дать модели описания функций; она решает, какую вызвать и с какими аргументами, а твой код выполняет.
5. **Агенты** — цикл «подумай → вызови инструмент → посмотри на результат → повтори», пока задача не решена.
6. **Evals** — наборы тестов для проверки качества: без них непонятно, стало лучше или хуже после изменения промпта.
7. **Fine-tuning** — дообучение модели на своих данных. Нужно реже, чем кажется: обычно сначала пробуют промпты и RAG.

### Минимальный пример вызова LLM через API (Python)

```python
# pip install anthropic
# export ANTHROPIC_API_KEY=...
import anthropic

client = anthropic.Anthropic()

response = client.messages.create(
    model="claude-sonnet-5-5",
    max_tokens=500,
    system="Ты опытный преподаватель. Объясняй просто и с примерами.",
    messages=[
        {"role": "user", "content": "Что такое токен в LLM? Ответь в 3 предложениях."}
    ],
)

print(response.content[0].text)
print(response.usage)  # сколько токенов ушло на вход и выход
```

Здесь видно всё, о чём шла речь выше:
- `system` — системный промпт, задаёт роль и правила поведения;
- `messages` — история диалога (роли `user` / `assistant`), её надо передавать каждый раз;
- `max_tokens` — лимит длины ответа;
- `usage` — токены, за которые ты платишь.

## 7. Мини-словарь

| Термин | Объяснение |
|---|---|
| **Токен** | Кусочек текста, единица, с которой работает модель |
| **Параметры / веса** | Числа внутри нейросети, которые подбираются при обучении |
| **Эмбеддинг** | Вектор чисел, представляющий смысл токена или текста |
| **Transformer** | Архитектура нейросети, на которой построены LLM |
| **Attention** | Механизм, позволяющий токенам учитывать друг друга |
| **Контекстное окно** | Максимум токенов в одном запросе (вход + выход) |
| **Inference** | Использование обученной модели (генерация ответа) |
| **Pre-training** | Первичное обучение на огромном корпусе текста |
| **Fine-tuning** | Дообучение под конкретную задачу или стиль |
| **RLHF** | Обучение на человеческих оценках ответов |
| **Prompt** | Входной текст-запрос к модели |
| **System prompt** | Инструкции, задающие поведение модели на весь диалог |
| **Temperature** | Параметр случайности генерации |
| **Галлюцинация** | Правдоподобный, но ложный ответ |
| **RAG** | Подмешивание найденных документов в промпт |
| **Агент** | Система, где LLM в цикле сама вызывает инструменты |
| **Multimodal** | Модель понимает не только текст, но и изображения, аудио и т.д. |
| **Open-weight модель** | Модель, веса которой можно скачать и запустить у себя (Llama, Mistral, Qwen) |

## 8. Главное, что стоит запомнить

1. LLM — это предсказатель следующего токена, который из-за масштаба научился «понимать» язык и рассуждать.
2. Внутри — трансформер с механизмом внимания и миллиардами параметров.
3. Обучение: pre-training → SFT → RLHF/RL. Базовая модель «знает», дообучение делает её «ассистентом».
4. Модель не имеет памяти, не знает свежих событий и может галлюцинировать — это нормально, с этим работают инженерно.
5. Работа AI-инженера — не обучать модели, а строить надёжные системы поверх них: промпты, RAG, инструменты, агенты, evals.
